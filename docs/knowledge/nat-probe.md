# NAT 探测 UDP 包设计和流向

## 分类

映射行为 Mapping：

- 端点无关 EndpointIndependent
- 地址相关 AddressDependent
- 地址和端口均相关 AddressAndPortDependent

过滤行为 Filtering：

- 端点无关 EndpointIndependent
- 地址相关 AddressDependent
- 地址和端口均相关 AddressAndPortDependent

## 数据包流向

### 准备

- 客户端 C：通过 HTTP 请求服务器 S1，从本次请求中获得 S1 本轮可供使用的两个 UDP 端点 P1 和 P2
    - 可以直接从本次请求中获得备用服务器列表，选择一个备用服务器作为 S2
    - 也可以自备服务器列表，选择一个作为备用服务器 S2
- 客户端 C：DNS 解析出 S1 和 S2 两个域名的 IP 地址，对于双栈测试，应解析出双 IPv4 地址做 IPv4 行为测试或双 IPv6 地址做 IPv6 行为测试
- 客户端 C：使用单个 UDP Socket，记录本地端点 C0:P0，全程确保本地端点不变

### 第 1.1 轮

- C->S1:P1 `[NAT-1S]{sessionId}{S2-HTTP}`，服务端看到客户端的公网端点并记为 C1:P1；同时服务端了解到客户端选择使用的备用服务器 S2
    - S1->S2 (HTTP) S1 请求服务器 S2 向客户端公网端点 C1:P1 发送 NAT 探测包，并在本次请求中获得了本次测试可供使用的两个 UDP 端点 P1 和 P2

### 第 1.2 轮（过滤行为测试）

- S1:P1->C1:P1 `[NAT-1R]{sessionId}{C1:P1}{S2.P1}{S2.P2}`，每 500ms 一次，共 4 次
- S1:P2->C1:P1 `[NAT-11]{sessionId}{C1:P1}{S2.P1}{S2.P2}`，每 500ms 一次，共 4 次
- S2:P1->C1:P1 `[NAT-12]{sessionId}{C1:P1}`，每 500ms 一次，共 4 次
- 客户端 C 一直等待收包直到超时：
    - 从 `[NAT-1R]` 包中验证 `C0:P0 == C1:P1`，相等说明客户端 C 直接暴露在公网，不相等说明存在 NAT（网络地址转换）
    - `[NAT-1R]` `[NAT-11]` `[NAT-12]` 的组合情况：
        - `true, true, true` => 端点无关
        - `true, true, false` => 地址相关
        - `true, false, false` => 地址和端口均相关
        - `true, false, true` => 不符合 RFC5780 过滤模型，可能是丢包等因素导致，测试无效，重测
        - `false, _, _` => 未收到主要回复，可能丢包严重，测试结果大概率不可信，重测
    - 超时，可能 UDP 丢包严重或当前网络不通，应重测

### 第 2.1 轮

- C->S2:P1 `[NAT-2S]{sessionId}`，每 500ms 一次，共 4 次，服务端看到客户端的公网端点并记为 C2:P1

### 第 2.2 轮（映射行为测试）

- S2:P1->C2:P1 `[NAT-2R]{sessionId}{C2:P1}`，每 500ms 一次，共 4 次
- 客户端 C 一直等待收包直到超时：
    - 验证 `C1:P1 == C2:P1`，相等说明映射为「端点无关」，否则进行第 3 轮测试
    - 超时，可能 UDP 丢包严重或当前网络不通，应重测

### 第 3.1 轮（映射行为测试补充）

- C->S2:P2 `[NAT-3S]{sessionId}`，每 500ms 一次，共 4 次，服务端看到客户端的公网端点并记为 C2:P2

### 第 3.2 轮

- S2:P2->C2:P2 `[NAT-3R]{sessionId}{C2:P2}`，每 500ms 一次，共 4 次
- 客户端 C 一直等待收包直到超时：

    - 超时，可能 UDP 丢包严重或当前网络不通，应重测
